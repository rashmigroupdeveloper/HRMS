## 2. Authoritative flow and database connections

| User action / screen | API and authoritative facts | Atomic behavior / visible outcome |
|---|---|---|
| Employee requests AR, OD or short permission in attendance | POST `/attendance/requests`; employee identity from authenticated context; `att.regularizations` references `wf.requests`; definitions remain runtime data | Kind/date/time/window/overlap rules validate before submission. Request/domain attachment and initial workflow opening share a transaction. No attendance P/OD is promised merely by submission. |
| Manager opens inbox or old notification | GET `/workflows/inbox` or `/workflows/requests/{id}`; `core.users`, effective role grants, `core.role_permissions`, employee org/reporting tree, `wf.request_steps` | Current scoped authority governs the queue and decision visibility. Requester/subject may inspect their own timeline. An exact historical ID never falls back to the next request. |
| Manager approves, rejects or sends back | POST `/workflows/requests/{id}/act`; locked open workflow step; audited reason; notification queue | An intermediate approval advances only. Final hooks and workflow decision commit together. Rejection/send-back notes are mandatory. Notification enqueue/timestamp proves queuing, not delivery acknowledgement. |
| Employee corrects a sent-back item | POST `/workflows/requests/{id}/resubmit`; registered domain validator, `att.regularizations` or `lv.applications`, then `wf.requests.payload` | Original request identity/subject/kind retained. Dates/times/leave eligibility and reservation are rechecked. Domain and canonical payload synchronize before restarting the chain. Original sent-back step remains visible. |
| Employee applies leave / comp-off | POST `/leave/apply`; `lv.leave_types`, pending applications, immutable `lv.ledger`, employee eligibility and calendar | Compute real units with existing sandwich/half-day policy. Existing pending reservation is excluded/credited correctly when revising that application. Do not trust client day totals. |
| Final AR/OD/leave approval | Shared `core/db/attendance-period.ts`; employee lock; company/month advisory lock also used by month close; `att.month_locks`, protected `att.day_records`; leave ledger when applicable | Locked month/manual override fails the whole decision. Whole-day approved rows clear stale session/type metadata as applicable. Approval, debit and intended day writes succeed together or roll back. Post-lock historical corrections remain HR work, not an automatic rewrite. |
| Employee views attendance / leave history | GET `/my/attendance` joins actual leave type; GET `/leave/applications/mine` joins workflow status; regularization request history | Calendar and history show committed facts and actual workflow status. No new display-only database counters or duplicate status columns were created. |

## 3. Attendance meaning — employee and manager context

| Display | Meaning and source | Important limit |
|---|---|---|
| P | Posted present day; processed punches or approved AR | It does not establish every payroll/OT input is approved. |
| A | Posted absent day after configured readiness checks | A missing day record is not A. Ordered session A:P remains distinct from a whole absent day. |
| OD | Approved official duty | Pending OD is visible as a request; it does not become posted OD until final approval. OD uses present visual treatment with its own literal label. |
| SL / CL / EL / CO or other configured type | Actual joined leave type | Name and paid/unpaid metadata come from the type. “SL” is sick leave, not an inferred medical eligibility determination. |
| HD/SL and session labels | Posted half-day plus leave type, or ordered session facts | Final payable-day/session/partial-OD treatment requires the recorded policy decision; this repair does not invent a divisor. |
| WO / H | Posted weekly-off / holiday | Do not reclassify OD or CO as weekly-off because a color mapping is missing. |
| Blank / not posted | Future not due or processing not yet complete | Employee is told the fact is missing. HR/manager must resolve feed/readiness exceptions before closing the month. |

Employee path: Attendance → day detail/request; Leave → application history → decision/correction. Manager path: Approvals badge/inbox → exact request → decision note/timeline. Scope and authority come from the API, not from whether a button is visible. Monthly counts are presentation summaries; reconciled payroll/muster rules remain separate acceptance work.
