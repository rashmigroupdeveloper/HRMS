## med.access_log

Records access to sensitive employee medical information.

| Field | What it means | Why it is kept | Simple example | Choices, where listed |
|---|---|---|---|---|
| `id` | The unique number the system gives this particular record. It is used to tell it apart from every other record in the same register. | Allows the correct record to be found and linked without relying on a name or description. | If two records have the same display name, their internal numbers still tell them apart. | Read the saved detail using its explanation; there is no fixed choice list shown here. |
| `questionnaire_id` | Identifies questionnaire connected to this record. | Keeps this record connected to the correct questionnaire, so related details can be checked together. | This record points to an existing entry in questionnaires instead of copying all of that entry’s details. | Read the saved detail using its explanation; there is no fixed choice list shown here. |
| `employee_id` | Employee to whom this record belongs; references the permanent main employee register. | Keeps this record connected to the correct employee, so related details can be checked together. | This record points to an existing entry in employees instead of copying all of that entry’s details. | Read the saved detail using its explanation; there is no fixed choice list shown here. |
| `actor_user_id` | Identifies actor user connected to this record. | Keeps this record connected to the correct actor user, so related details can be checked together. | This record points to an existing entry in users instead of copying all of that entry’s details. | Read the saved detail using its explanation; there is no fixed choice list shown here. |
| `action` | Operation or decision recorded by this event; permitted codes are listed with the field constraints. | Gives staff and the system a consistent choice for the classification described here. | “read” means Read classification for action. | read: Read classification for action.; write: Write classification for action.; withdraw: Withdraw classification for action.; denied: Denied classification for action. |
| `reason` | Recorded business justification for the operation or decision. | Preserves the explanation so another person can understand the record later. | The saved wording answers the question described above; it should explain the specific case rather than just say “done”. | Read the saved detail using its explanation; there is no fixed choice list shown here. |
| `ip` | Client IP address captured as access or submission where the information came from; personal/security descriptive information. | Keeps this specific detail with the record so staff can identify, explain or check it in context. | A saved browser or connection detail can help an authorized administrator investigate which sign-in or submission produced the event. | Read the saved detail using its explanation; there is no fixed choice list shown here. |

NULL means no time is recorded. | Read the saved detail using its explanation; there is no fixed choice list shown here. |
